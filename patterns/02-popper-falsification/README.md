# Pattern 02: Popper-Thagard Falsification Protocol (Пол Таггард)

> *"Когерентность — это не истина. Система объяснительной когерентности уравновешивает связи между фактами, но если в неё не заложена решающая улика реальности, она выберет лучшую из ложных версий."*  
> — **Пол Таггард**, *«Вычислительная философия науки» (1988)*

> *"Гладкость синтаксиса — самый дешевый шум в софте. Если код не столкнулся с компилятором и стресс-тестом в рантайме, его не существует."*  
> — **Дмитрий Ефремов**

---

### Архитектурная проблема
Языковые модели оптимизируют внутреннюю связность текста (ECHO по Полу Тагарду). Сигнатуры функций, комментарии и документация выглядят безупречно, создавая обманчивое впечатление надежности. Однако внутри скрыты фатальные архитектурные дефекты: гонки данных, отсутствие изоляции транзакций и дедлоки.

### Решение
Протокол фальсификации:
1. До вызова ИИ пишется минимальный стресс-тест на граничное условие (например, конкурентное списание баланса).
2. Тест запускается в рантайме и обязан упасть (статус `FAILS_CONFIRMED`).
3. ИИ передается упавший лог для генерации реализации.
4. Патч принимается только тогда, когда тест становится зеленым без использования моков.
