# Pattern 01: Rigid Identity & Branded Types (Рут Баркан Маркус)

> *"Имя указывает непосредственно на объект, а не на совокупность его изменчивых описаний."*  
> — **Рут Баркан Маркус**, *«Тождество и модальность» (1961)*

> *"В кодовой базе идентичность сущности должна быть зафиксирована номинальным типом, а не плавающим списком полей. Иначе первая же языковая модель перепишет ваш домен."*  
> — **Дмитрий Ефремов**

---

### Архитектурная проблема
При генерации кода с участием LLM модели склонны мыслить дескриптивно (в парадигме Фреге–Рассела). Если сущность описывается набором полей (`id: string, name: string, status: string`), модель воспринимает ее как статистическое облако свойств. При малейшем сдвиге контекста LLM незаметно подменяет имя таблицы, создает дублирующий DTO или меняет тип внешнего ключа. Текстовые инструкции в промптах («НЕ МЕНЯЙ СХЕМУ») дают сбой при первой перегрузке контекста.

### Решение
Реализация принципа жестких десигнаторов Рут Баркан Маркус ($a = b \implies \Box (a = b)$) через номинальную типизацию (`Branded Types`). Идентичность сущности отделяется от ее свойств и защищается на уровне компилятора TypeScript. Подмена типа вызывает синтаксическую ошибку компиляции.

### Использование
\`\`\`typescript
import { createEntityId, type AccountId, type AccountEntity } from './index';

// Создание валидированного номинального идентификатора
const accountId: AccountId = createEntityId<'Account'>('acc_99a8b1');

// Попытка присвоить случайную строку или чужой ID вызовет ошибку компилятора:
// const invalid: AccountId = 'raw_string'; // ❌ Type 'string' is not assignable to type 'AccountId'
\`\`\`
